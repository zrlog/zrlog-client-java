# 文章保存超时后对账（独立待处理问题）

用户报告：文章保存 POST 的同步静态化可能超过 120 秒，网关返回 Cloudflare HTTP 524 或客户端超时，但文章数据已经落地。代理地址选择修复不处理此问题。

后续实现应在保存响应超时后仅用 GET 按 alias 查找唯一文章、读取详情，对比目标内容、属性和状态；更新操作还应检查文章 ID 和预期版本。对账成功应区分“文章已保存”与“静态化已完成”，不能仅凭文章存在就报告发布完成。

不得自动重发结果不确定的 POST。回读失败、alias 不唯一、内容或版本不一致时，应明确提示保存结果尚未确认，避免误报成功或重复写入。

验证应覆盖 HTTP 524、客户端等待响应超时、落地后的成功对账、内容或版本冲突、回读失败，并断言整个流程只有一次 POST。已有 SSE 发布完成和明确失败事件的处理应继续保留。
